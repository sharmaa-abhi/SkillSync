# Production Supabase Authentication Fix — SkillSync AI

## 1. Root Cause
1. **Disconnection from Supabase Auth**:
   Previously, the registration route (`POST /api/auth/register`) only wrote records to the PostgreSQL `public."User"` table via Prisma. It **never invoked Supabase Auth** (`auth.users`). Consequently, **Supabase Dashboard → Authentication → Users** showed *"No users in your project"*.
2. **Production 503 Mismatch on Vercel**:
   On localhost, `DATABASE_URL` was loaded from `.env`. On Vercel, `.env` is gitignored. Because `DATABASE_URL` on Vercel was missing, contained an unencoded password (`@` instead of `%40`), or lacked serverless pooler parameters, Prisma initialization threw an error that was converted to `HTTP 503 Service Unavailable`.
3. **Fragile Single-Database Coupling**:
   By directly calling the **Supabase Auth REST API** (`https://gjkiumovdcpbyaqkuwyz.supabase.co`) via the official `@supabase/supabase-js` client, registration and authentication now talk directly to Supabase Auth over HTTPS, creating real Supabase Auth users instantly without pooler latency or connection drops.

---

## 2. Why Localhost Worked
* Localhost had a local `.env` file containing the connection string to PostgreSQL.
* Localhost accessed the database via Node.js without Vercel's isolated serverless container environment.
* However, even on localhost, **no user was being created in Supabase Auth** because the code was bypassing `supabase.auth`.

---

## 3. Why Production Failed
* `.env` is never pushed to GitHub or Vercel.
* The Vercel deployment did not have `DATABASE_URL`, `SUPABASE_URL`, or `SUPABASE_SECRET_KEY` configured in the Vercel Dashboard.
* The API route returned 503 because it caught the missing/failed database connection and masked it as a connectivity error.
* Supabase Auth had 0 users because `POST /api/auth/register` was never creating Supabase Auth accounts.

## 7. API Changes
* **`POST /api/auth/register`**:
  * Step 1: Validates request payload (presence, email format, minimum 8-character password).
  * Step 2: Creates user directly in **Supabase Auth** via `supabaseAdmin.auth.admin.createUser({ email, password, email_confirm: true, user_metadata: { name } })`.
  * Step 3: Returns **409 Conflict** (`DUPLICATE_EMAIL`) if email already exists in Supabase Auth.
  * Step 4: Synchronizes user into PostgreSQL with matching UUID (`id: supabaseUser.id`).
  * Step 5: Returns **201 Created** with `{ success: true, user }`.
* **`NextAuth` (`src/lib/auth.ts`)**:
  * In credentials `authorize`: Authenticates directly with `supabasePublic.auth.signInWithPassword({ email, password })`.
  * Fast, secure, and fully verified by Supabase Auth with fallback to demo accounts.
